# idea2launch · 双宿主确认页规范

> 适用范围：L1 阶段闸门 ×9、L2 关键决策 ×3（[triggers.md](triggers.md)），以及 conduct.md C4 矩阵「必须确认」档的任何时刻（如删文件、对外发布前确认）。
> 分工：本文件只定**结构与行为**（要素、选项、防呆、回写）；视觉与可达性细节一律引用 `modules/ui-spec/`（唯一事实源），不在此复制。

## 一、共同要素（两宿主一致，缺一不呈现）

1. **大白话摘要**：三句以内——做了什么、产出在哪、下一步是什么；术语须已按 C2 翻译。
2. **后果声明**：签字意味着什么 / 退回意味着什么，两行并列、先于选项出现（C2 后果前置）；签字后果不轻描淡写（含消耗影响时如实说）。呈现「回退上一闸门」选项时，回退与退回的后果须分别说清——回退＝退回上一阶段重做，比退回影响面大。
3. **选项**：L1 默认五选项——**看细节 / 改了再签 / 签字 / 退回 / 回退上一闸门**（阶段 1 用其特例集：继续/调整/转草图档/放弃——G1 之上无前一道闸门，不设回退项）；L2 按其决策内容给 2-3 个实质选项＋「其他」。选项文案与语义表见 [triggers.md](triggers.md) L1。
4. **防呆四禁**：
   - 禁默认选中任何确认类选项；
   - 禁倒计时/限时确认；
   - 禁隐藏或弱化「退回」类否定选项；
   - 禁一页混多个闸门——每闸门独立呈现；被退回后重新呈现须附「改了什么」一句话。
5. **一次一闸门**：同一时刻只有一个待决闸门；用户未明确选择前不得推进。

### 决策附证（L2 关键决策追加要素，两宿主一致）

L2 关键决策（UI 方向/技术栈/开发票批准，[triggers.md](triggers.md) L2）的推荐项**必附证据，禁裸推荐**——用户拍的是明白板，不是感觉：

1. **简式摘要 ≤100 字置顶**：这是什么决策＋推荐哪项＋一句关键理由——用户只看这一行也能拍板；超出 100 字的硬证据（对照表/数据/来源明细）不放摘要层。
2. **硬证据进「看细节」展开**：证据明细带来源链接与检索日期（C1；对照表格式见 [research-funnel.md](research-funnel.md) §2 第③步），折叠在细节层，不挤决策视野。
3. **三评估**（各一两句大白话，紧随摘要）：**可行性**——能不能做、卡点在哪；**必要性**——不做会怎样、是否非现在做不可；**性价比**——成本几何、有无更省的替代路径。
4. **明确推荐项**：证据与三评估之后必须落到一个推荐项＋理由链（理由引用证据，禁「都行」「看喜好」）；选择权仍在用户（C3/C6）。草图档自动采用时，同一份证据与理由链照常留痕（`rationale`＋decisions.log，triggers.md L2）。

## 二、CLI 宿主（会话结构化提问）

1. **优先用宿主的结构化提问能力**（选项式）：问题文本＝摘要＋后果声明，选项＝五选项逐字；用户点选即为其决定。
2. **无结构化提问能力时**：普通提问＋编号列表（1 看细节 / 2 改了再签 / 3 签字 / 4 退回 / 5 回退上一闸门），**禁标注或暗示推荐默认项**；用户可用编号或选项原文回复。
3. **自由文本映射**：明确的认可类简短回复（「好/可以/签字吧」）按「签字」处理，但前提是本闸门的摘要与后果声明已完整呈现过；含糊回复（「再说/看看/嗯」）不映射任何选项，追问一次；映射结果在写回 `state.json` 的 `note` 中记录用户原话。
4. **看细节的实现**：就地展示产出文件的关键段落或全文路径；展示后**必须**回到同一闸门重新给五选项，不得视为默认通过。
5. **改了再签的实现**：闸门记 `returned`，按用户意见修改产出后重新走一遍共同要素 1-3；修改说明一句话带出。

## 三、浏览器宿主（HTML 确认页）

**何时用**：产出本身适合在浏览器看时（典型：阶段 3 原型评审）；M1 各闸门的**决定动作默认仍走 CLI 宿主**，浏览器页是辅助呈现与外行人友好的阅读面。两种宿主可并存于同一闸门（页面看细节＋会话里签字）。

1. **页面结构**（自上而下）：
   - 标题：阶段 N 闸门名（如「阶段 3 · 设计冻结确认」）；
   - 摘要区：共同要素 1；
   - 后果区：签字后果与退回后果两栏并列（共同要素 2）；
   - 细节折叠区：`<details>` 内放产出文件清单与关键段落，默认收起；
   - 选项区：五选项各一个按钮，**等权重排布**，否定类选项（退回/改了再签/回退上一闸门）与确认按钮视觉同级。
2. **防呆**：确认类按钮**不做默认焦点、不绑定回车键**；无倒计时；按钮点击后不立即视为签字——进入第 3 条的结果回传。
3. **结果回传**：点击任一选项按钮 → 页面显示一个结果文本框，自动填入一行结果（如「我的选择：签字（阶段 3 设计冻结，2026-XX-XX）」），提示用户复制回会话；会话收到该结果行才写回 `state.json`。
4. **技术约束**：单文件 HTML＋内联 CSS，`file://` 双击可开，禁外部 CDN（与原型同规，见 `modules/ui-spec/prototype-spec.md`）；落位 `idea2launch/<阶段目录>/确认页-<闸门名>.html`。
5. **样式与可达性（引用不复制）**：
   - 设计 token 取 `modules/ui-spec/ui-spec.md` §9 新手默认套装（变量整块复制，不自行调值）；
   - 按钮与表单状态对照 `modules/ui-spec/components.md` 状态矩阵；
   - 可达性硬指标对照 `modules/ui-spec/interaction-a11y.md`（对比度 ≥4.5:1、焦点可见、键盘可达、触控目标 ≥44px、行高 ≥1.7）；
   - 交付前按 `modules/ui-spec/review-checklist.md` 相关必过项自检。

## 四、签字回写（两宿主同一出口）

1. 任一宿主拿到用户的明确选择后：`signed` → `gates` 追加记录＋`current_stage` 前进；`returned` → `gates` 追加记录（附原因），留在本阶段；「回退上一闸门」→ 向前一道 gate 追加 `returned`（`note` 注明「回退重做」），`current_stage` 退回上一阶段（[state-protocol.md](state-protocol.md) §2.3）。
2. 写回即唯一写路径（C4 第 3 行）；确认页本身不存储任何状态——状态只在 `state.json`。
3. 草图档不改变本规范：L1 闸门仍须真人签字，只有 L2 允许自动采用推荐项（triggers.md L2）。
