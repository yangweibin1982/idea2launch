# idea2launch · 周蒸馏简报与上游反馈（evolution-brief）

> 定位：本插件自带的自进化机制——你的项目走完向导后，经验不该只躺在档案里。本规范定义「蒸馏简报」：把一段时间的坑、缺口、别扭之处整理成**两栏产出**——一栏优化你自己的智能体工作流，一栏反馈给插件维护者。全程本地整理；任何对外提交都必须经你同意（C4 矩阵第 8 行：对外发布必须确认）。
> 触发时机（三选一即可，不依赖任何定时任务能力）：①阶段 9 建反馈入口时介绍本机制（一句话即可）；②用户回访迭代时（阶段 2 读教训后）主动提供一次；③用户随时说「整理一下最近的坑／做个简报」。
> 与自进化状态机的分工：教训台账（`8-delivery/教训.md`）＝原始层，本简报＝蒸馏层；已晋级的教训不再重复出现在简报里。

## 一、收集（只读，C4 矩阵第 1 行：直接做）

1. 本项目 `idea2launch/8-delivery/教训.md`（阶段 8 第⑦步留痕）；
2. `idea2launch/state.json` 的 `open_gaps` 与 `decisions.log` 中的缺口类条目（缺口台账）；
3. 用户口头的近期不顺：问一句「最近用起来有没有哪里别扭？」，口头收集。

## 二、两栏产出（逐条给用户看，等裁决）

### 栏一：优化你自己的工作流（建议，经同意才落）

- 每条格式：**现象**（什么坑）→ **建议**（给智能体规则加一句什么预防规则，一句话式）；
- 落点：宿主全局规则文件（如 AGENTS.md）或项目内 `AGENTS.md`——写入宿主配置属「必须确认」档，**逐条征得同意后由智能体执行写入**，并向你复述写了什么、写到哪；不想改就跳过，插件不强加。

### 栏二：值得让维护者知道的（issue 草稿，脱敏）

- 收什么：插件本身的缺陷、文档看不懂的地方、流程卡壳点、改进建议；
- 脱敏红线：草稿只描述**插件**的问题——你自己项目的业务内容、名称、数据一律占位化（如 `<你的数据>`），不进草稿；
- 每条草稿：标题（一句话）＋正文（现象／复现步骤／期望行为），全文 ≤20 行。

## 三、提交上游（经同意，两种形态）

1. 宿主有 `gh` CLI 且已登录 GitHub：逐条展示草稿 → 你明确说「提交第 N、M 条」→ 智能体执行 `gh issue create -R yangweibin1982/idea2launch --title "<标题>" --body "<正文>"`，逐条回报 issue 链接；
2. 无 `gh` 或未登录：给出草稿全文＋议题页地址（`https://github.com/yangweibin1982/idea2launch/issues/new`），由你复制粘贴亲手提交。

**插件永不自动对外提交**——没有你的明确同意，栏二永远停在草稿态（C4 矩阵第 8 行）。

## 四、留痕与闭环

- 简报落 `idea2launch/9-operate/蒸馏简报-<YYYY-MM-DD>.md`：两栏全文＋你的裁决（哪条采纳/提交/跳过）；
- 已提交的 issue 编号回写简报；维护者修复后你更新插件（git pull）即可验证闭环——同族问题复发时，下份简报引用旧 issue 编号，方便维护者关联。
