## 二、执行序（六步，顺序执行，不得跳步）

### 第 1 步 · 需求收集：盘点已有信息（不问新问题，只盘存量）

1. **摘评估报告**（已签字，可当已确认事实引用）：目标用户、痛点真实性结论、竞品差异化、红旗、第 12 维 MVP 蔓延结论。
2. **摘用户原话**：从阶段 1 会话与评估报告引用的用户表述中，把每一条「我想要…」逐条列出。
3. **产出《需求盘点表》**（会话内呈现，不单独落盘）：每行＝`候选需求｜来源（用户原话/评估报告）｜状态（已确认·用户签过字 ／ 待拷问·仅线索）`。
4. **红线**：评估报告里智能体的「建议」不等于用户要——标「待拷问」，进第 2 步当面问；盘点表本身不新增任何需求（C3）。

### 第 2 步 · 新手版拷问（18 问 · 4 批，每问三要素）

**拷问总则**：

- **分批**（C2 禁单次大量）：每批 ≤5 问，共 4 批；一批一屏内呈现完。
- **默认值友好**：每问必带【推荐默认】；用户回「按推荐／不知道／随便」（草图档可整批「全按推荐」）＝采纳推荐项，采纳的问号记入 PRD 来源列（`拷问 Qx·采纳推荐`）。
- **术语首现必译**（C2）：每问自带【术语翻译】；答案里用户冒出的新行话，智能体复述时也要翻译。
- **「以后再说」入缺口**：用户答「以后再说/下一版再说」的功能 → 登记 `state.json` 的 `open_gaps`（id=`gap-` 序号，stage=2），同时进 PRD 不做清单「以后还做吗＝是」列（[../state-protocol.md](../state-protocol.md) §5）。
- **答录留痕**（C1）：每批结束复述一遍「我的理解是…对吗」，用户点头才算该批答完。

#### 第一批 · 用户与核心功能（Q1–Q5）

**Q1｜这个应用是给谁用的？他们在什么情况下会拿出来用？**
- 【推荐默认】按评估报告目标用户给一句具体推荐（示例：「先服务你自己＋身边最多 10 个人，别一上来想全国用户」）。
- 【术语翻译】目标用户——第一批**真会打开它**的人，不是「所有人」。
- 【为什么问这个】用户是谁决定界面繁简与功能取舍；答「给所有人用」通常等于还没想清楚，须追问。

**Q2｜打开这个应用，用户**最常做的一件事**是什么？（没有它应用就不成立的那件事）**
- 【推荐默认】从评估报告痛点结论提炼一句（示例：「打开就能记录一条内容，10 秒完成」）。
- 【术语翻译】核心功能——应用的存在理由；砍掉它用户就没有理由再来。
- 【为什么问这个】这题的答案就是 PRD 第一条 P0；如果用户列出三件「都最常做」，说明还没聚焦，帮他排顺序而不是照单全收。

**Q3｜除了核心那件事，哪些是「有了更好、没有也能用」的？**
- 【推荐默认】从盘点表挑 2-3 条线索给用户勾选，推荐只留 1-2 条进第一期。
- 【术语翻译】次要功能——没有也能用，有了更好用；行话叫 P1（第二优先级）。
- 【为什么问这个】区分「必须做/最好做」是防蔓延的第一刀；不问，用户会默认全都要。

**Q4｜你幻想过、但感觉可以缓一缓的功能是什么？**
- 【推荐默认】把用户说出的全部登记为「以后再说」（open_gaps），并明说「记下了，第一期不做，但不会忘」。
- 【术语翻译】缓一缓——登记进「以后再说」清单，第一期不做；不是拒绝，也不占第一期的工。
- 【为什么问这个】这类想法不问出来，会开发中途反复冒出来打断节奏；先问出来登记，用户安心、范围锁死。

**Q5｜应用里的内容从哪里来？第一批数据谁来填？**
- 【推荐默认】第一版由用户自己（或导入现成表格）填第一批，不做公开征集。
- 【术语翻译】数据——应用要记住的信息，一条记录＝一张卡片；冷启动——上线第一天什么内容都没有的空壳状态。
- 【为什么问这个】决定上线第一天应用是「能用」还是「空房间」；也决定要不要做批量录入（行话叫导入）。

#### 第二批 · 数据与权限（Q6–Q10）

**Q6｜用户填进去的数据，谁能看到？**
- 【推荐默认】默认只有填的人自己能看（最安全），分享/公开列为以后再说。
- 【术语翻译】隐私——只想让自己或特定人看到的信息；权限——谁能干什么、不能干什么的规定。
- 【为什么问这个】决定要不要做「分享」功能，以及数据要保护到什么程度；答错这题最容易出隐私事故。

**Q7｜要不要账号（注册登录）？**
- 【推荐默认】最简方案：数据只在本机/单人用 → 第一版不做登录；数据要分人看 → 只做邮箱注册一种方式。
- 【术语翻译】注册——第一次登记身份；登录——以后凭这套身份进来，系统认出「还是你」；第三方登录——用微信/Google 这类已有账号一键进来，不用另记新密码。
- 【为什么问这个】账号体系是新手最容易低估工作量的部分（要管密码找回、防乱注册）；能不做就不做，能最简就最简。

**Q8｜需要提醒吗？比如到点弹一下、发封邮件。**
- 【推荐默认】第一版不做主动提醒，打开应用时看到未读提示就够。
- 【术语翻译】推送——应用主动把消息发到你手机/电脑上，哪怕你没打开它；站内提示——只有打开应用才看得见的提醒。
- 【为什么问这个】主动推送要接外部服务、可能花钱、还各平台规则不同；很多「我以为要推送」的场景其实站内提示就够。

**Q9｜要不要传文件或图片？**
- 【推荐默认】仅图片、单张限 5MB 内；文档/视频列为以后再说。
- 【术语翻译】上传——把你手机/电脑里的文件送到帮应用存东西的电脑上（那台 24 小时开机的电脑行话叫服务器）。
- 【为什么问这个】文件能力直接推高存贮成本和出事面（传什么违法文件、空间满了）；限类型限大小是最省心的防呆。

**Q10｜手机上用还是电脑上用？**
- 【推荐默认】响应式网页一套通吃（手机电脑都自动排好版），不单独做手机 App。
- 【术语翻译】响应式——同一套页面在手机、平板、电脑上都自动调整排版；网页版——浏览器打开就用，不用安装。
- 【为什么问这个】决定阶段 3 设计与阶段 4 技术的大方向；「都要」通常成立（响应式），但必须当面确认而不是默认。

#### 第三批 · 边界与经营（Q11–Q15）

**Q11｜界面要几种语言？**
- 【推荐默认】只中文。
- 【术语翻译】多语言（行话叫 i18n）——界面文字能切换成不同语言显示；做一种语言，全部页面文字就要全套翻译并长期维护。
- 【为什么问这个】语言每加一种，工作量和长期维护近似翻倍；用户常高估外国用户比例。

**Q12｜免费还是要收钱？怎么收？**
- 【推荐默认】第一版免费，收钱功能登记「以后再说」。
- 【术语翻译】订阅——按月/按年付费续用；支付通道——帮网站收钱的中间商（支付宝/微信支付/Stripe 这类）。
- 【为什么问这个】一旦收钱，就牵出退款、发票、合规一整串事，工作量翻几倍；「先免费验证有没有人用」几乎是新手唯一正解。

**Q13｜需要一个管理员专用的后台吗？**
- 【推荐默认】要一个极简后台，只管两件事：看用户列表、管内容（下架违规/删错误数据）。
- 【术语翻译】管理后台——只有管理员能进的页面；增删改查（行话 CRUD）——对记录做四件事：添加、查看、修改、删除。
- 【为什么问这个】有别人用就要有人管；不问，上线第一天出乱子时连个处理入口都没有。

**Q14｜现成的数据要搬进来吗？以后要把数据带走吗？**
- 【推荐默认】支持「导出」成表格文件（一键把数据存成 Excel 能打开的文件带走）；「导入」看 Q5 的回答再定。
- 【术语翻译】导入——把现成表格文件读进应用；导出——把应用里的数据存成文件带走；CSV——用逗号分隔的纯文本表格文件，Excel 可直接打开，是搬数据的通用行李箱。
- 【为什么问这个】导出是用户的数据主权，也是「不被应用锁死」的退路；有退路，用户才敢把重要数据放进来。

**Q15｜要和别的工具打通吗？（微信/日历/表格软件…）**
- 【推荐默认】第一版一律不打通，全部登记「以后再说」。
- 【术语翻译】打通（行话叫集成/对接）——让两个应用互相传数据；API——程序之间传话的规矩，对方按规矩开门，你按规矩敲门。
- 【为什么问这个】每个打通都依赖别家服务：要申请、可能收费、人家改版你就坏；第一版打通越多死得越快。

#### 第四批 · 落地与验收（Q16–Q18）

**Q16｜上线之后，谁来管它（修问题、看运行状况）？**
- 【推荐默认】前三个月由本流程（阶段 9 轻运营）随叫随到；长期由用户自己或其指定的人接手。
- 【术语翻译】运维——上线后保证应用一直正常运转、出问题有人修；备份——定期把数据原样抄一份另存，坏了能恢复。
- 【为什么问这个】「做完」不等于「有人管」；没人管的应用三个月后大概率打不开，这一题决定阶段 9 怎么设计。

**Q17｜怎么算成功？三个月后发生什么，你会觉得「值了」？**
- 【推荐默认】「你自己每周用它 ≥3 次连续 4 周＋身边 3 个人不用教就会用」，用户不同意再换。
- 【术语翻译】成功标准——事先写下的可核对目标（一个数字或一眼能判断的现象），做完照着对答案。
- 【为什么问这个】没有成功标准，做完永远不知道该加功能还是收工，蔓延从这里开始；这题答案直接进 PRD 成功标准节。

**Q18｜第一版最晚什么时候要？**
- 【推荐默认】按草图档节奏给出量级预估（示例：「正常推进约几轮会话；具体排期阶段 5 给出，估计非承诺」）。
- 【术语翻译】里程碑——把「做完」切成几个能中途检查的站；上线——把做好的应用装到 24 小时开机的电脑上，别人随时能打开。
- 【为什么问这个】期限反过来决定第一版砍多狠：越紧，P0 越要砍到最小；没有期限，蔓延没有天然刹车。

### 第 3 步 · PRD 组装

1. 按模板 [../templates/prd.md](../templates/prd.md) 组装，落 `idea2launch/2-requirements/PRD.md`；模板内「填法提示」注释逐节照办，交付时删净注释。
2. 功能优先级沿用三级：P0＝必须有／P1＝最好有／P2＝以后再说；来源列必须落到「用户原话／拷问 Q 编号·采纳推荐／评估报告（已签字）」三者之一（C1）。
3. **禁写技术实现**（C6 不越层）：语言、框架、数据库、部署方式一律不出现——那是阶段 4 的事；PRD 只写「要什么」。
4. 术语首现必译（C2）：按 §三 对照表，成文中技术词第一次出现加括号大白话。
5. 写完后自检一遍 PRD 八节是否齐全、每条功能与不做项是否有来源。

### 第 4 步 · 用户故事拆分

1. 按模板 [../templates/user-stories.md](../templates/user-stories.md) 拆分，落 `idea2launch/2-requirements/用户故事.md`，编号 `US-001` 起（阶段 5 排期按编号引用，编号规约见模板）。
2. **覆盖面硬要求**：PRD 三节每条 P0 功能至少 1 条 P0 故事；异常场景（填错了/断网了/手滑删了）至少 1 条——主流程顺、出岔子不崩。
3. 每条故事带「假如／当／那么」大白话验收标准（禁「好用」「快速」类没法核对的词，C1）；来源列指回 PRD F-xx 或用户原话（C3）。
4. 拆完向用户播报一句盘点：「共 N 条故事：P0×a、P1×b、P2×c，其中异常场景 x 条」。

### 第 5 步 · MVP 范围确认（防蔓延三栏）

1. 呈现**三栏清单**（依据评估报告**第 12 维 MVP 范围蔓延**结论＋第 2 步拷问结果）：
   - **本期做（P0）**：逐条列出，合计不超过一屏（C2）。
   - **本期不做但登记在案（P1/P2＋open_gaps）**：含每个「以后再说」的缺口编号，让用户看见「没被扔掉」。
   - **明确不做**：预判用户可能期待但本期没有的功能（如自动备份、多端同步、分享海报），逐条请用户点头——**禁静默塞入**（C3 范围取舍必问）。
2. 一次确认条目 >5 条则分批呈现（C2）。
3. 用户在此步提出新增功能 → 按 triggers.md L3「加功能类」处理：说明对 MVP 边界的影响，纳入则增量进 PRD 并重走受影响确认，不纳入则入不做清单。
4. 三栏全部过目并获用户口头确认后，才允许进第 6 步闸门。

### 第 6 步 · 闸门：G2-requirements（PRD 签字页）

1. 按 [../confirmation-pages.md](../confirmation-pages.md) 共同要素呈现，顺序不可倒：
   - **大白话摘要**（≤3 句）：做了什么（盘点→拷问 18 问→PRD＋故事）、产出在哪（`idea2launch/2-requirements/` 两个文件）、下一步是什么（阶段 3 画原型）。
   - **后果声明**（先于选项，C2）：签字＝需求定稿进设计，此后改需求＝改已签字产出须重签（C6）；退回＝留在阶段 2 按意见修改。
   - **默认四选项**：看细节／改了再签／签字／退回（语义与写回规则见 [../triggers.md](../triggers.md) L1）。

## 三、术语翻译纪律（C2 在本阶段的实施细则）

1. **首现必译**：对用户说的每句话里，技术词第一次出现紧跟一句大白话；此后可直用。禁用术语解释术语（「幂等就是保证幂等性」＝没翻译）。
2. **拷问题自带翻译**：第 2 步每问的【术语翻译】即首现场；PRD/故事成文中再按本表首现补译。
3. **高频术语对照表**（就地内嵌，拷问与成文共用；表外新术语按同一风格现译）：

| 术语 | 大白话（禁术语解释术语） |
|---|---|
| PRD | 把「这个应用要做什么」写成一份清单，让所有人看了签字认账的文件（行话叫产品需求文档） |
| 用户故事 | 用一句「作为谁，我想做什么，以便得到什么」写下的需求小卡片 |
| 验收标准 | 事先约定好的「怎样才算做对了」，做完照着一条条核对 |
| MVP | 最小可用版本——功能刚够第一批人用起来就先上，好用的以后再加 |
| API | 程序之间传话的规矩——一个程序按这个规矩向另一个程序要数据、办事情 |
| 增删改查（CRUD） | 对一条记录就做四件事：添加、查看、修改、删除 |
| 权限 | 谁能干什么、不能干什么的规定（比如普通用户只能看自己的，管理员能管全部） |
| 注册／登录 | 注册＝第一次登记身份；登录＝以后凭这套身份进来，系统认出「还是你」 |
| 服务器 | 24 小时开机、帮应用存东西和干活的电脑——你关机了别人也能访问 |
| 数据库 | 像一个超大号的 Excel，专门存放应用要记住的所有信息 |
| 前端／后端 | 前端＝你看得见点得着的页面；后端＝幕后管数据和规矩的部分 |
| 响应式 | 同一套页面在手机、平板、电脑上都自动排好版 |
| 上传／下载 | 上传＝把你的文件送到服务器上；下载＝从服务器把文件拿到你设备上 |
| 导入／导出（CSV） | 导入＝把现成表格读进应用；导出＝把数据存成文件带走；CSV＝逗号分隔的纯文本表格，Excel 能直接打开 |
| 部署／上线 | 把做好的应用装到服务器上，让别人的浏览器随时能打开 |
| 运维／备份 | 运维＝上线后保证一直正常运行、出问题有人修；备份＝定期把数据原样抄一份另存，坏了能恢复 |
