# 阶段 8 · 交付（Delivery）· 阶段细则 ○

> 本文是九阶段中第 8 阶段（交付○简版）的执行细则。一句话：智能体换上「交付工程师」角色（角色卡见 [../roles/role-8-delivery.md](../roles/role-8-delivery.md)），把验收通过的应用变成**一键运行包**——双击就能跑——配上启动说明、上线检查单、用户手册，经 **G8-delivery** 交付确认后，给用户「下一步可发布」提示＋引导入口（M2 起：想发布按 [../cloud-deploy.md](../cloud-deploy.md) 陪跑指路；发布动作仍全部用户亲手，不代发布）。
> 互引分工：职责/输入/输出/禁止事项见角色卡；闸门写回见 [../state-protocol.md](../state-protocol.md)（G8 行）；装载顺序见 [../triggers.md](../triggers.md)；确认页呈现见 [../confirmation-pages.md](../confirmation-pages.md)。**本文 §2 是一键运行包的打包规约（唯一出处）**。
> 纪律基线：[../disciplines/conduct.md](../disciplines/conduct.md)（C1–C7）＋[../disciplines/engineering.md](../disciplines/engineering.md)（E4 凭据/E5 实例化复核）。本阶段高频条款：C1「双击可跑」必须实测过、E4 包内零凭据、C4 矩阵第 8 行对外发布必须确认（M1 不代执行）。

## 1. 执行序（七步，按序执行，不得跳步）

### 第①步 AGENTS.md 终检＋交付摘要卡

1. 复核用户项目根 `AGENTS.md`（阶段 6 首个开发动作已实例化，见 [stage-6-build.md](stage-6-build.md) 第①步）：E5 必选项零裁剪项齐全；启动命令/测试命令与应用实际逐字核对（C1）。
2. 按 [../templates/generated-project-AGENTS.md](../templates/generated-project-AGENTS.md) §4 追加「项目交付摘要」卡。

### 第②步 一键运行包打包（规约全量见 §2）

按 §2 规约在用户项目根生成启动器与启动说明；`.env` 类真实配置不入包，只留 `.env.example`（键名齐全、值全空——E4-2；角色卡禁止事项 2）。

### 第③步 本机实跑验证（「双击可跑」必须实测过，C1）

1. 双击启动器 → 等浏览器自动开 → 主流程点一遍（至少核心那件事走通）。
2. 运行证据留痕进 `idea2launch/8-delivery/`（终端输出摘录或截图说明＋一句「于本机实测通过」＋实测时间）。删临时打包文件先列清单再删（角色卡 C4）。

### 第④步 三份文档

1. `启动说明.md`：按 §2.3 话术规约写（三步＋两条故障兜底，每步带「看到什么算成功」）。
2. `上线检查单.md`：按模板 [../templates/launch-checklist.md](../templates/launch-checklist.md) 组装——凭据零命中（E4-3 grep 指引）/敏感信息扫描/基本可达性三条/备份提示；**本阶段只备单不执行发布**（C4 矩阵第 8 行：对外发布必须确认，M1 不代执行）。
3. `用户手册.md`：按模板 [../templates/user-manual.md](../templates/user-manual.md) 组装——这应用是什么/怎么开始/常见问题；素材来源＝PRD（这是什么）＋启动说明（怎么开始）＋测试报告已知问题（常见问题）；面向最终用户，通篇大白话零行话。

### 第⑤步 闸门 G8-delivery（交付确认）

1. 按确认页规范呈现，顺序不可倒：大白话摘要 ≤3 句（交付了什么——运行包在哪、双击哪个文件、本机实测过；三份文档在哪；下一步是什么——确认后进轻运营，想发布另有指引）＋**后果声明先于选项**（确认＝项目交付、进入轻运营；退回＝留在阶段 8 按意见改）＋**默认五选项**：看细节／改了再签／签字／退回／回退上一闸门（[../triggers.md](../triggers.md) L1）。
2. 写回（七步写入法，写路径唯一）：确认 → gates 追加 `G8-delivery` `signed`、`current_stage=9`；退回 → 追加 `returned`（附原因）留阶段 8；回退上一闸门 → `G7-quality` 追加 `returned` 退回阶段 7（重走验收）。
3. **两档一致**：真人签，草图档不例外，禁代签（C4 矩阵第 5 行）；连续两次退回 → 触 C3；签字后追加台账卡。

### 第⑥步 「下一步可发布」提示＋引导入口（发布动作仍全部用户亲手）

交付确认后固定呈现三句（话术规约，术语已按 C2 翻译过可直用）：

1. 「你的应用现在能在你自己的电脑上跑。如果以后想让别人随时随地打开它，可以把它**发布**到网上（行话叫部署/上线）——那一步会把应用装到一台 24 小时开机的电脑上，费用与账号都由你自主决定。」
2. 「想自己动手：技术方案 §一 已定往哪儿搬的方向（本机/静态托管/一体化平台/租服务器自托管），`上线检查单.md` 帮你发布前逐项核对，`启动说明.md` 是日常使用入口。」
3. 「想让我帮忙：直接说『帮我部署到＿＿』——我会先与你确认目标平台和费用再动手。**现在我不会替你发布任何东西**（发布必须你亲自确认）。」

**引导入口（M2 起）**：用户表示想发布或说「帮我部署到＿＿」时，进入引导式部署向导陪跑指路——[../cloud-deploy.md](../cloud-deploy.md)：替用户实查平台候选（带来源证据）、备好每一步材料、陪验证上线；**注册账号、点部署按钮、付钱等一切发布动作仍全部用户亲手**（C4 矩阵第 8 行），向导里每一步都标「谁动手」。用户不想发布——到上面三句为止，不追问不推销（C6 不扩权）。

### 第⑦步 教训留痕（交付确认后，给下一轮迭代留本项目的坑）

交付确认（第⑤步 `signed`）后，在 `idea2launch/8-delivery/教训.md` 记**一条**本轮真实发生的教训，三行式：

```
坑：{这次踩了什么，一句大白话——现象与代价}
修：{最后怎么解决的，一句}
教训：{下一轮迭代开工前该记住什么，一句}
```

- **只记一条、必须真实**：来源＝构建日志/测试报告/闸门退回原因里真实出现过的事，禁编造、禁凑数（C1）；本轮真没有值得记的 → 写一行「本轮无遗留教训」同样合法，禁硬凑。
- **用途**：下一轮迭代（或存量迭代任务）走阶段 2 时开场先读此文件（[stage-2-requirements.md](stage-2-requirements.md) 开场装载清单）——同样的坑不踩第二遍。
- 记完向用户播报一句记了什么；用户明示不用记 → 跳过并在会话留痕一句（不静默，C7-4）。

## 2. 一键运行包打包规约（唯一出处）

### 2.1 包内容（用户项目根生成，四件）

| 件 | 文件 | 说明 |
|---|---|---|
| 启动器 | `启动.bat`（Windows）／`启动.command`（macOS） | **按用户当前操作系统二选一生成**（骨架 A 纯静态项目可省，见下方裁剪注）；换系统时回本阶段补生成另一个；形态模板见 [../templates/run-package.md](../templates/run-package.md)（按骨架 A/B/C/D 分形态，各节含包内容清单与自检） |
| 启动说明 | `启动说明.md` | 三步＋两条故障兜底（§2.3） |
| 应用本体 | 源码目录＋README＋`.env.example` | 与开发完成态一致；`.env` 类真实配置禁入包（E4-2） |
| 流程档案 | `idea2launch/` 全套 | 交付物的文档面，随项目走 |

**纯静态裁剪注（骨架 A／无后端项目适用）**：以上各件按纯静态形态裁剪，裁了什么在开场播报与包内 README 各记一句（裁剪留痕、禁静默删，精神同 E5-3）：

- 启动器可省——双击 `index.html` 即用；启动说明第 1 步退化为「双击打开应用文件夹里的 index.html」一行说明。若仍生成启动器，§2.2 第 0 条编码铁律**仍全量适用**（不因形态裁剪）。
- 不适用项：§2.2 第 1 条「启动本地服务」与第 2 条「端口写死常量」（无本地服务、无端口）、§2.3 兜底一（端口占用）——对应铁律与端口兜底话术整体跳过，不算违规。
- 替代自检（顶替「双击启动器实测」）：双击 `index.html` 实测页面可开＋断网状态下再开一次仍可用——纯静态页禁外部 CDN 引用（与原型规约同源）；实测留痕同第③步规约。
- 三步话术静态形态变体（第 1 步见上，第 2/3 步改写）：第 2 步＝把主流程点一遍（看到：页面正常、该出的结果出得来＝成功）；第 3 步＝以后想用，再双击 `index.html`，或把它收藏进浏览器（看到：同一个应用页面＝成功）。兜底二改写：「双击没反应＝确认双击的是 `index.html` 文件本身，不是它所在的文件夹」。

### 2.2 启动器脚本四条铁律

0. **编码铁律（不守此条，双击即闪退）**：Windows `启动.bat` 必须 **CRLF 换行**，且内容二选一——**纯 ASCII**（注释用英文），或**首行 `@echo off`＋次行 `chcp 65001 >nul` 后再出现中文**（UTF-8 无 BOM）。禁止 UTF-8 中文直接裸写在无 chcp 的 bat 里：cmd 默认按 GBK 解析，中文 rem/echo 行会碎成乱码「命令」，脚本在 `start` 执行前就崩（实测闪退，T10 收口发现 F-12）。生成后自检：`cmd //c 启动.bat` 零「不是内部或外部命令」输出、退出码 0。
1. **只做三件事**：按项目 README 的包管理器标准命令准备依赖 → 以约定端口启动本地服务 → 拉起默认浏览器打开该端口。
2. **除启动端口为写死常量外禁任何魔法**：禁静默修改用户配置、禁联网下载脚本、禁写系统设置；脚本内每条命令都能在项目 README 或包管理器标准用法里找到出处（用户看得懂、可自行复查，C1）。
3. **出错说人话**：依赖装不上/端口被占/启动失败时，终端打印一行大白话（出了什么事＋可以怎么办），禁闪退、禁只抛技术堆栈（E1-6 同源）。

### 2.3 启动说明.md 话术规约（三步＋两条兜底）

- **三步**（每步一个动作＋「看到什么算成功」，C2）：
  - 第 1 步：双击「启动」文件（Windows 双击 `启动.bat`；macOS 双击 `启动.command`——首次若被拦，右键选「打开」一次即可）。看到：弹出一个终端窗口开始滚动文字＝成功。
  - 第 2 步：等几秒，浏览器会自己打开应用。看到：应用页面出现＝成功。
  - 第 3 步：以后想用，打开浏览器在地址栏输入 `http://localhost:{{端口}}` 就能回到它。看到：同一个应用页面＝成功。
- **兜底一（端口占用）**：「提示端口被占用＝这扇门被别的程序先占了。改法：用记事本打开启动器文件，把开头的端口数字（{{端口}}）改成一个别的数（如 8080 改 8081），保存后重新双击。」
- **兜底二（浏览器没自动开）**：「浏览器没自己开＝手动打开你平时用的浏览器，在地址栏输入 `http://localhost:{{端口}}`。」
- 话术纪律：通篇大白话、每步一个动作（C2）；技术词首现必译；禁任何凭据字面量（E4）；端口数字与启动器内常量一致（逐字核对，C1）。

### 2.4 macOS 补充

`.command` 首次运行会被系统安全机制拦一次——启动说明写清放行办法（右键「打开」一次），用大白话讲，不许吓着用户。
