## 一、静态形态（骨架 A）

**什么时候用**：技术方案 §一 骨架＝A 纯静态页——无后端，数据全存 localStorage（存在你自己浏览器里的一小块空间），断网也能用。

**包内容清单**（用户项目根，三件）：

| 件 | 文件 | 说明 |
|---|---|---|
| 应用页面本体 | `index.html`（入口）＋页面需要的伴随文件＋`README` | README 里记一句「本包按纯静态形态裁剪」（裁剪留痕，stage-8 §2.1 裁剪注同款，禁静默删） |
| 启动说明 | `启动说明.md` | 按 stage-8 §2.3 三步话术＋纯静态形态变体（变体唯一出处＝stage-8 §2.1 裁剪注，本模板不复述） |
| 流程档案 | `idea2launch/` 全套 | 交付物的文档面，随项目走 |

**双击自检（两条，全过才算包齐；留痕同 stage-8 第③步——「于本机实测通过」＋实测时间写进 `idea2launch/8-delivery/`）**：

1. 双击 `index.html` → 页面能打开。
2. 断开网络再双击一次 → 页面仍能用。纯静态页禁外部 CDN 引用（页面里禁写「从别家网站拉样式/脚本」的地址）——查到了就改成本地文件，重新打包，本自检从头再来。

## 二、Node 形态（骨架 B/C/D · Node 路径）

**什么时候用**：骨架 B/C/D，且技术方案 §一 后端件是 Node 路径（Express 类服务器——后端骨架模板见 [skeleton-node.md](skeleton-node.md)）。

**包内容清单**（用户项目根，七件）：

| 件 | 文件 | 说明 |
|---|---|---|
| 服务器 | `server.mjs` | 后端本体，阶段 6 已按 api-contract 换真；探活端点 `/api/health` 禁删（阶段 7 探活与本包自检都靠它） |
| 页面 | `public/` | 前端页面目录，服务器托管它 |
| 依赖与启动清单 | `package.json` | 装哪些依赖、怎么启动都登记在这；`start` 脚本＝`node server.mjs` |
| 配置示例 | `.env.example` | 键名齐全、值全空（E4-2）；真实 `.env` 禁入包 |
| 启动器 | `启动.bat`（Windows）／`启动.command`（macOS） | **按用户当前操作系统二选一生成**；写法唯一出处＝[../stages/stage-8-delivery.md](../stages/stage-8-delivery.md) §2.2 四条铁律——**含第 0 条编码铁律（bat 必须 CRLF 换行＋纯 ASCII，或 `chcp 65001 >nul` 之后才出现中文；不守此条双击即闪退）**。本模板不复述、不弱化：生成前逐条对照，生成后按其自检命令验证 |
| 启动说明 | `启动说明.md` | 按 stage-8 §2.3 话术（三步＋两条兜底） |
| 流程档案 | `idea2launch/` 全套 | 同静态形态 |

**依赖安装话术**（装依赖＝C4 矩阵第 6 行「建议后做」——先说明、用户不反对再动手）：

> 「接下来我要运行 `npm install`：它会按 `package.json` 的清单，从 npm 官方源（registry.npmjs.org——Node 官方的依赖包仓库）下载本项目需要的依赖包，装进项目文件夹的 `node_modules/` 里（本项目约 {{包数}} 个包、预计下载约 {{体积}}，以实际清单为准）。装完应用才能启动；装一次就行，以后启动会自动跳过已装的。」
> {{包数}}／{{体积}} 按依赖清单实数填，禁拍脑袋（C1）。用户反对＝不装——包不齐不交付，回 stage-8 第②步。

**启动自检（命令与 [skeleton-node.md](skeleton-node.md) §五 逐字一致）**：

1. 项目根执行 `npm install`。
2. 执行 `node server.mjs`（或 `npm start`——`package.json` 的 start 脚本就是这一条；带 `.env` 配置运行用 `node --env-file=.env server.mjs`，Node 20.6+）。
3. 浏览器开 `http://127.0.0.1:3000/api/health` → 返回 `{"ok":true,...}`＝服务活着（端口以 `.env` 的 `PORT` 为准，默认 3000）。
4. 交付硬门不变：双击启动器实测仍按 stage-8 第③步执行（「双击可跑」必须实测过，C1）——上面 1–3 步是毛坯自检，替代不了它。

**结构性启动步骤（示例命令，实查后填／核对）**：

1. 建虚拟环境（venv＝项目自带的独立 Python 小房间，装东西不弄脏系统）：`python -m venv .venv`（示例）
2. 进小房间装依赖：激活 venv 后执行 `pip install -r requirements.txt`（示例；依赖来自 PyPI 官方源 pypi.org——Python 官方的依赖包仓库；激活命令 Windows 与 macOS 写法不同，以官方文档为准）
3. 起服务：`uvicorn main:app`（示例——`main`/`app` 换成实际入口文件名与对象名；端口等参数以官方新手文档为准）
4. 浏览器开 `http://127.0.0.1:{{端口}}` → 应用页面出现＝服务活着

**自检与实测**：毛坯自检＝上方 1–4 步跑通；交付硬门仍＝双击启动器实测（stage-8 第③步，C1）。
