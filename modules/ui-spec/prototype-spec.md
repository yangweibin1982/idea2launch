# 原型技术规范（单文件 HTML）

> idea2launch 第 3 阶段（设计）子模块三件套之②：本文件规定 LLM 生成原型的**技术约束**——产物既要让非技术用户断网双击就能打开，又要能无损进入可视化编辑层（GrapesJS 0.23.6 内核）无损导出。
> 工序（先做什么后做什么）见 `page-design.md`；token 数值与预设见 `ui-spec.md` §9；交付自检见 `review-checklist.md`。生成起点模板见 `templates/prototype-template.html`。
> **兼容性实证**：V1 Spike（2026-10-03，GrapesJS 0.23.6，file:// 协议）已验证「内联 token CSS＋语义标签＋data-pid」原型经导入→导出后 CSS 变量、var() 引用、@media、语义 DOM、data-pid 全部保留（A1–A4 断言 PASS）。因此本文件对 CSS 变量与 @media **放行**（可用），但仍保留生成期结构约束（§4）——实证达标≠可随意写。

## 1. 文件形态

- **每页一个单文件 HTML**，文件名 `<page>.html`；`<page>` 与该页 data-pid 页段一致（小写英文＋连字符，如 `home.html`、`order-list.html`）。
- `<head>` 内单个 `<style>` 内联全部样式；**零外部依赖**：无框架/字体/图标 CDN、无外链图片、无外链脚本、无 `@import`、无任何网络请求。
- `<meta charset="UTF-8">`＋`<meta name="viewport">`＋`<html lang="zh-CN">` 必带。
- **图片只用两种**：内联 SVG dataURL（`<img src="data:image/svg+xml,...">`，带 `alt`）或纯色占位块（`div`＋`role="img"`＋`aria-label`＋token 背景色＋宽高标注）。禁外链图。
- **禁 `<script>`**：原型是静态审核稿，不含任何交互逻辑；页面跳转用真实 `<a href>`（相对文件名）；按钮行为由开发阶段实现，编辑器的交互由 visual-editor 提供。
- **断网 `file://` 双击可开**是验收动作，不是口号：生成后须实际断网双击打开核验。

## 2. token 纪律

- **基座**：`:root` 变量块整块取自 `ui-spec.md` §9 三套预设之一（或已拍板的项目品牌推导版），**不删变量、不改变量名**——三套预设变量同名，编辑器的「token 预设切换」靠同名整体替换，改名即破坏切换。
- **强制 `var()` 六类**：颜色、间距、字号、圆角、阴影、动效时长——样式规则里这六类出现字面值即违规（magic number）。
- 修改任何颜色值后必须复校对比度（正文 ≥4.5:1，大字与图形 ≥3:1，见 `ui-spec.md` §2/§9）。

**例外白名单**（六类之外或结构常量，允许字面值）：

| 例外 | 示例 | 为什么允许 |
|---|---|---|
| 1px 边框/分隔线宽度 | `border: 1px solid var(--border-subtle)` | 结构常量，不随主题变；粗细走 token 无收益 |
| 0 与结构性关键字 | `margin: 0`、`border: none`、`flex: 1`、`width: 100%` | 无主题语义，不存在「换肤」需求 |
| 行高比值 | `line-height: 1.7` | 排印比例非六类 token（数值须满足 ui-spec §3：中文 ≥1.7） |
| 透明度 alpha 段 | `rgba(17, 24, 39, 0.05)`（自绘遮罩时） | 遮罩是效果非主题色；阴影优先用 `--shadow-*` 封装 |
| 视口断点值 | `@media (max-width: 768px)` | 断点体系固定值（640/768/1024/1280/1536，ui-spec §4），非主题变量 |

> 判定口诀：**这个值换一套皮肤时要不要跟着变？要→必须 `var()`；不要→查白名单，白名单没有→按违规处理。**

## 3. 结构纪律

- **语义标签**：`header / nav / main / section / article / footer` 表达页面结构；`div` 只做纯布局容器，禁「div 万物」。
- **data-pid 逐区块标注**：格式 `data-pid="<page>-<block>-<seq>"`（协议权威定义见战役规格《ui-design-layer》§6；编辑器侧新增区块编号 `<page>-new-<seq>` 与 freeze 重整规则同见该节与 `visual-editor/EDITOR-SPEC.md`）。生成侧示例：`home-hero-01`、`list-toolbar-01`、`form-basic-02`。
  - `<seq>` 两位数字从 01 起，同页不重不漏；区块增删后接续编号。
  - 可编辑区块**无遗漏无重复**（review-checklist H 必过项）。
  - 纯装饰（分隔线、背景块、容器壳）不标。
- **区块粒度判据**：「**用户会想整体改动的一个视觉单元**」。三问：①用户会不会想改它的文字或图？②把它删掉或挪走，页面还成立吗？③它内部还有没有值得单独改的更小单元？——②答「是」即一个区块；③答「是」则拆细。一屏 5–12 个区块为宜。
- `<block>` 命名用英文短词：`nav / hero / features / toolbar / table / form / head / meta / body / actions / footer / kpi / chart` 一类，见 `page-design.md` 布局库骨架示例。

## 4. GrapesJS 编辑兼容约束（生成期仍须遵守）

实测保真的部分（放心用）：`:root` CSS 变量与 `var()` 引用、`@media` 规则、语义标签 DOM、`data-pid` 属性——导入导出全程保留（V1 Spike A1–A4）。

**生成期约束**（实证达标≠可随意写，以下仍为硬规则）：

1. **选择器扁平**：类/标签/属性选择器为主；后代嵌套最多两层（`.card .title` 可以，`.a .b .c .d` 禁）——编辑器组件化拆分后深层匹配易断裂。
2. **`:root` 块整体保留**：不拆分、不内联、不按选择器重写。
3. **常规流布局**：flex/grid 为准；**禁绝对定位画布**（把元素用 `position:absolute` 摆在画布上）——编辑层移动、增删元素后绝对布局即崩。
4. **禁 `<script>`、禁 `@import`**（同 §1）。
5. **同名 class 一处定义**：避免同一类名多处重复定义（编辑器改样式按类名整类生效，重复定义会互相覆盖、行为不可预期）。

## 5. 多页原型

- 文件命名同 §1；**页间导航一律相对文件名**（`<a href="order-list.html">`），禁绝对路径、禁 `file:///` 前缀——换机器断链且泄漏本机目录结构。
- 全部页面用**同一套 token 基座**（同一次拍板）：`:root` 块逐文件原样一致，禁止 A 页基座 B 页自创。
- 可视化编辑器**逐文件载入**（一次编辑一页）；导出修改包按文件回传（`edited.html`＋`edits.json`，回传协议见战役规格 §8 与 `visual-editor/EDITOR-SPEC.md`）。

## 6. 反例速查

| # | 反例 | 为什么不行 |
|---|---|---|
| 1 | 颜色写字面值 `#2563eb` 而不用 `var(--primary)` | token 预设切换靠变量替换，裸值永远不变色——用户换主题时这处「焊死」 |
| 2 | 引 Tailwind/Bootstrap/字体/图标 CDN | 断网打不开；且编辑器导入后样式全丢，等于白做 |
| 3 | lorem ipsum 或「这里是介绍文字」占位 | 用户无法判断业务含义，原型审核失去意义（真实文案是硬要求） |
| 4 | 绝对定位画布局（元素钉死在坐标上） | 编辑层一移动、一增删，布局立刻崩；响应式三视口必挂 |
| 5 | 可编辑区块缺 data-pid 或重复 | 编辑器改动无法定位追溯，freeze 后技术阶段无法按 pid 映射组件 |
| 6 | 原型里写 `<script>` 做交互 | 原型是静态审核稿；编辑器导入导出不保 JS 逻辑，写了一定坏 |
| 7 | 深嵌套选择器 `.header .nav .item .link` | 编辑器组件化后匹配断裂，样式改不动或改错片 |
| 8 | 页间链接写 `file:///C:/Users/...` 绝对路径 | 换机器即断链；还把作者本机目录结构泄漏进开源仓 |
