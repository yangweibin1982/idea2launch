## 怎么接入一个增强（维护者/贡献者视角，三步）

1. **写契约**：在 `optional/` 新建契约文件——写清「要能做什么操作」「没有服务时怎么回退」「在哪些阶段挂点」（照 knowledge/code-intel 两份的样子）。
2. **注册**：在 `core/references/enhancements.md` 第 2 节概览表加一行、第 5 节挂点表加挂点（有新挂点面时）。
3. **过四关**：按 enhancements.md 第 6 节「纯净性四关」逐条自检，任一不过不入库。

## 维护者参考栈（不随插件分发）

维护者自己的环境里有一套私有参考栈：GBRAIN（Postgres＋pgvector 知识库）、bge-m3 向量模型、CODEGRAPH（代码索引）。它们是上述契约的**参考实现**，但**不随插件分发**、路径不在本仓出现。

- **为什么不分发**：私有栈带着维护者的数据、密钥面与运维负担，对外部用户既不可复现也不该可见；分发实现等于分发负担。
- **参考实现不等于唯一实现**：分发的只是「契约＋参考实现说明」，**实现可替换**——任何 MCP 兼容的知识服务、任何符号级代码索引工具，按契约接入即可；什么都没有时，各适配器写明的本地回退完整可用。

## 什么不放本目录（负面清单）

- **个人域技能**：领域专属、带个人资料的内容不入（原因见伴生技能 README 末节）。
- **维护者私有实现**：私有知识服务/代码索引的连接方式、配置、密钥面一律不入——入库的只有契约与「实现可替换」声明。
- **有硬依赖的工具**：缺了就跑不通主流程的东西不属于「可选增强」，那是核心缺陷，该修 core 而不是在这儿加挂点。

## 变更纪律

- 本目录内容的变更必须**同步注册表**（enhancements.md 第 2/5 节）——注册表是挂点的唯一登记处，契约在而注册表没有＝未生效。
- vendored 技能只走同步仪式（见伴生技能 README），不做手工改动；两份适配器契约的修改须重跑其「完成判据」节。

## 纯净模式承诺

删掉本目录，九阶段流程一步不少（降级规则见 enhancements.md 第 4 节）。本目录所有内容入库前都过 enhancements.md 第 6 节「纯净性四关」（平台无关／新手价值／脱敏／维护者专属归引擎层）。
