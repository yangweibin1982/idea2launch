# 代码智能适配器契约（code-intel-adapter）

> 本文是可选增强层「代码智能」的适配器契约：一个代码索引工具要接入 idea2launch，需要能回答哪三问、没有索引工具时怎么用 grep/glob 回退、在哪些挂点怎么用。注册表与挂点总表见 [../core/references/enhancements.md](../core/references/enhancements.md)。
> 铁律一句话：**改码之前先盘链路——谁调用它、它调用谁、影响面多大；工具可以没有，这三问不能不问。**

## 1. 契约：三个操作

接入的代码索引工具须支持以下三操作（实现形态不限——符号图谱、语言服务、全文索引均可，只要能回答这三问）：

| 操作 | 大白话 | 输入 | 输出 |
|---|---|---|---|
| 符号定义搜索 | 「这个东西在哪定义的」 | 符号名（函数/类/常量） | 定义位置（文件＋行号） |
| 调用方查找 | 「谁在用它」 | 符号名 | 调用它的位置清单 |
| 调用流程探索 | 「一件事从头到尾怎么流转」 | 入口符号或自然语言问题 | 按顺序的调用链/相关符号组 |

## 2. 回退：grep/glob（平台自带，人人可用）

- 无索引工具时，三问用文本检索回答：定义搜索≈按「声明形」关键词搜；调用方查找≈全库搜符号名；调用流程探索≈从入口符号逐跳追。
- **精度代价与读法口径**：文本检索会把注释与字符串也命中，清单偏大——按「**宁多勿漏**」口径读影响面，命中条目逐条剔除误报，禁因嫌多而略读。
- **查无＝也有结论**：两轮不同关键词仍无命中 → 该改动点大概率是新代码（无存量调用方），清单如实记「无调用方（查法：〈关键词〉，日期）」，禁不查就默认「没人用」。
- 回退不改变第 3 节的纪律本身：三问照问、清单照出，只是慢一点、粗一点。

## 3. 挂点（两处）

### 阶段 6 · 改码前的「改动点全链路调查」（硬纪律）

这条纪律来自实战教训：只看眼前一行顺手改，改出了别处调用方的回归。**动一张票（或迭代轮的小改动）之前**，对每个改动点执行三问，并产出**影响面清单**：

1. **谁调用它**（调用方查找）：改签名、改行为会波及哪些调用点；
2. **它调用谁**（定义搜索＋调用流程探索）：下游依赖哪些文件与服务；
3. **影响面清单**：受影响的上下游与关联面（含跨文件依赖、配置、模板、文档映射处）——在票评论或 `idea2launch/6-build/构建日志.md` 留一行痕。

清单一行的最小形状：**改动点｜上下游（谁调用/被谁调）｜关联面（配置/模板/文档）｜证据来源（工具名或 grep 关键词）**——四段有则写，无则标「无」，留痕不是为了好看，是为了改坏了能倒查当时看见了什么。

调查发现牵连面超出票面 → 停下呈报用户（问题＋证据＋建议），**不静默扩大改动面，也不静默漏改**——这是行为规范 C6（禁超票面顺手改）在改码前的落实动作。

### 阶段 4 · 技术方案影响面评估

迭代项目（在存量代码上做新功能、改方案）在阶段 4 评估「这个选型/方案要动多少现有代码」时，用三操作盘候选方案对现有调用链的影响面，结论写进技术方案的影响面一节；首次从零建项目没有存量代码，本挂点自然不触发。

## 4. 参考实现注记

维护者在自己的环境中以一套私有代码索引工具（符号级代码图谱）作为本契约的参考实现；该实现不随插件分发、路径不出现在本仓。任何符号级代码索引工具按契约接入即可；无工具时第 2 节 grep/glob 回退完整可用。
